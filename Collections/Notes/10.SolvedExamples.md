Solved Example 1: Two Sum

Difficulty: Easy
Concepts: HashMap, arrays, lookup
Importance: Very high

Problem

Given an integer array nums and an integer target, return the indexes of two numbers whose sum equals the target.

Assume exactly one valid answer exists and the same element cannot be used twice.

Example:

Input:
nums = [2, 7, 11, 15]
target = 9

Output:
[0, 1]
Approach

For each number, calculate the complement:

complement = target - current number

Then check whether the complement has already appeared.

If it has, return the stored index and the current index.

Otherwise, store the current number and its index.

Complete solution
import java.util.HashMap;

class Solution {

    public int[] twoSum(int[] nums, int target) {

        HashMap<Integer, Integer> map = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {

            int complement = target - nums[i];

            if (map.containsKey(complement)) {

                return new int[] {
                    map.get(complement),
                    i
                };
            }

            map.put(nums[i], i);
        }

        return new int[0];
    }
}
Why do we check before inserting?

Consider:

nums = [3, 3]
target = 6

At index 0, the map is empty, so the first 3 is stored.

At index 1, the complement is 3, and the map contains the first element's index.

The algorithm returns:

[0, 1]

The same array element is never used twice.

Complexity
Time: Expected O(n).
Space: O(n).
What this teaches you

You should recognize this structure:

Calculate what you need.
Look it up in a map.
If found, solve the problem.
Otherwise, store the current information.

This pattern appears in many more advanced problems.

Solved Example 2: First Non-Repeating Character

Difficulty: Easy
Concepts: String, HashMap, frequency counting

Problem

Given a string, return the index of its first character that occurs exactly once.

Example:

Input:  "leetcode"
Output: 0

The character 'l' occurs only once and appears first.

Complete solution
import java.util.HashMap;

class Solution {

    public int firstUniqChar(String s) {

        HashMap<Character, Integer> freq = new HashMap<>();

        for (int i = 0; i < s.length(); i++) {

            char ch = s.charAt(i);

            freq.put(ch, freq.getOrDefault(ch, 0) + 1);
        }

        for (int i = 0; i < s.length(); i++) {

            if (freq.get(s.charAt(i)) == 1) {
                return i;
            }
        }

        return -1;
    }
}
Why are there two loops?

The first loop calculates all frequencies.

The second loop checks characters in their original order.

A HashMap does not preserve the order in which keys are encountered, so iterating through its keys is not the right way to identify the first unique character.

Edge cases
"leetcode" -> 0
"loveleetcode" -> 2
"aabb" -> -1
"a" -> 0
"" -> -1
Complexity
Time: O(n).
Space: O(k), where k is the number of distinct characters.
Solved Example 3: Implement a queue using two stacks

Difficulty: Easy to Medium
Concepts: Stack, queue, amortized complexity

Problem

Implement a queue using two stacks.

The queue should support:

push(x): Insert an element.
pop(): Remove the front element.
peek(): Return the front element.
empty(): Check whether the queue is empty.
Approach

Use two stacks:

input: Stores incoming elements.
output: Supplies elements for removal.

When the output stack is empty, transfer all elements from the input stack to the output stack.

This reverses their order.

Complete solution
import java.util.ArrayDeque;
import java.util.Deque;

class MyQueue {

    private Deque<Integer> input;
    private Deque<Integer> output;

    public MyQueue() {

        input = new ArrayDeque<>();
        output = new ArrayDeque<>();
    }

    public void push(int x) {

        input.push(x);
    }

    public int pop() {

        moveIfNeeded();

        return output.pop();
    }

    public int peek() {

        moveIfNeeded();

        return output.peek();
    }

    public boolean empty() {

        return input.isEmpty() && output.isEmpty();
    }

    private void moveIfNeeded() {

        if (output.isEmpty()) {

            while (!input.isEmpty()) {
                output.push(input.pop());
            }
        }
    }
}
Important implementation detail

This implementation assumes pop() and peek() are called only when the queue is nonempty, as is typical in the corresponding LeetCode problem.

If you were designing a general-purpose queue API, you would need to define and implement behavior for empty-queue operations.

Why does the transfer work?

Suppose the input stack contains:

Bottom: 10, 20, 30 :Top

Transferring each item to the output stack reverses the order:

Bottom: 30, 20, 10 :Top

Now 10 is on top and is removed first.

Complexity
push(): O(1).
pop(): Amortized O(1).
peek(): Amortized O(1).
empty(): O(1).

Each element is transferred at most once from one stack to the other
