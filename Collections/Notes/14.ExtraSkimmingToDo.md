# PART 2 — The foundations behind Java collections

## Lesson 1: Primitive types, wrapper classes, and generics

Before using collections, understand one important Java rule.

Java has primitive types such as:

```java
int
long
double
char
boolean
```

But Java collections store objects rather than primitive values.

For example, this is invalid:

```java
ArrayList<int> numbers = new ArrayList<>();
```

This is correct:

```java
ArrayList<Integer> numbers = new ArrayList<>();
```

`Integer` is the wrapper class for `int`.

Other useful wrapper classes include:

| Primitive | Wrapper     |
| --------- | ----------- |
| `int`     | `Integer`   |
| `long`    | `Long`      |
| `double`  | `Double`    |
| `char`    | `Character` |
| `boolean` | `Boolean`   |
| `float`   | `Float`     |
| `short`   | `Short`     |
| `byte`    | `Byte`      |

### What are generics?

Generics specify which types a collection can store.

```java
ArrayList<Integer> numbers = new ArrayList<>();
ArrayList<String> names = new ArrayList<>();
HashMap<String, Integer> scores = new HashMap<>();
HashSet<Character> letters = new HashSet<>();
```

In this example:

* `ArrayList<Integer>` stores integers.
* `ArrayList<String>` stores strings.
* `HashMap<String, Integer>` maps strings to integers.
* `HashSet<Character>` stores unique characters.

Consider:

```java
ArrayList<Integer> numbers = new ArrayList<>();

numbers.add(10);
numbers.add(20);

// numbers.add("hello"); // Compilation error

int first = numbers.get(0);
```

Java can check the types you put into the collection at compile time.

### What is autoboxing?

Autoboxing automatically converts a primitive value into its wrapper object.

```java
ArrayList<Integer> numbers = new ArrayList<>();

numbers.add(10);
```

Conceptually, Java converts the primitive `10` into an `Integer` object.

### What is unboxing?

Unboxing converts a wrapper object back into its primitive value.

```java
Integer value = 25;

int number = value;
```

Java automatically extracts the integer value.

### Important exception: null unboxing

Consider:

```java
Integer value = null;

int number = value;
```

This causes a `NullPointerException`.

Why? Because Java cannot extract an `int` from a nonexistent `Integer` value.

This is particularly important when working with maps.

For example:

```java
HashMap<Integer, Integer> map = new HashMap<>();

Integer value = map.get(100);
```

If key `100` is absent, `get()` returns `null`.

Therefore, this can be dangerous:

```java
int value = map.get(100);
```

It throws a `NullPointerException` if the key is missing.

A safer alternative is:

```java
int value = map.getOrDefault(100, 0);
```

**Remember:** `getOrDefault()` returns the supplied default when the key has no mapping. If a key is explicitly mapped to `null`, however, `getOrDefault()` returns that null value.

### Quick assessment

**Question 1:** Why does `ArrayList<Integer>` work, but `ArrayList<int>` does not?

**Question 2:** What happens when you unbox a null `Integer`?

**Question 3:** What does `HashMap<Integer, Integer>.getOrDefault(key, 0)` help you avoid?

# PART 3 — ArrayList

## Lesson 2: Understanding ArrayList

An `ArrayList` is a dynamically sized list.

A normal array has a fixed length after creation.

```java
int[] numbers = new int[3];
```

You cannot make this array larger simply by calling an `add()` method.

An `ArrayList`, however, can grow as you insert elements.

```java
import java.util.ArrayList;

ArrayList<Integer> numbers = new ArrayList<>();

numbers.add(10);
numbers.add(20);
numbers.add(30);

System.out.println(numbers);
```

Output:

```text
[10, 20, 30]
```

## 1. Essential methods

| Operation        | Method                                | Meaning                         |
| ---------------- | ------------------------------------- | ------------------------------- |
| Add              | `list.add(value)`                     | Append an element               |
| Insert           | `list.add(index, value)`              | Insert at an index              |
| Access           | `list.get(index)`                     | Retrieve an element             |
| Modify           | `list.set(index, value)`              | Replace an element              |
| Remove by index  | `list.remove(index)`                  | Remove an element               |
| Remove by value  | `list.remove(Integer.valueOf(value))` | Remove a matching integer       |
| Check membership | `list.contains(value)`                | Check whether a value exists    |
| Find an index    | `list.indexOf(value)`                 | Return the first matching index |
| Get size         | `list.size()`                         | Return the number of elements   |
| Check empty      | `list.isEmpty()`                      | Check whether the list is empty |
| Clear            | `list.clear()`                        | Remove all elements             |
| Convert to array | `list.toArray()`                      | Return an array of objects      |

Remember:

* An array uses `array.length`.
* An `ArrayList` uses `list.size()`.

### Example: insert, modify, and remove

```java
import java.util.ArrayList;

public class ArrayListDemo {
    public static void main(String[] args) {
        ArrayList<Integer> nums = new ArrayList<>();

        nums.add(10);
        nums.add(20);
        nums.add(30);

        nums.add(1, 15);

        nums.set(0, 5);

        nums.remove(2);

        System.out.println(nums);
        System.out.println(nums.size());
    }
}
```

Output:

```text
[5, 15, 30]
3
```

Let's examine the operations.

Initially:

```text
[10, 20, 30]
```

After inserting `15` at index `1`:

```text
[10, 15, 20, 30]
```

After replacing index `0` with `5`:

```text
[5, 15, 20, 30]
```

After removing index `2`, which contains `20`:

```text
[5, 15, 30]
```

### The important `remove()` trap

Consider:

```java
ArrayList<Integer> nums = new ArrayList<>();

nums.add(10);
nums.add(20);
nums.add(30);

nums.remove(1);
```

This removes the element at index `1`, which is `20`.

But what if you want to remove the integer value `20`?

Use:

```java
nums.remove(Integer.valueOf(20));
```

This distinction is important because `ArrayList<Integer>` has both `remove(int index)` and `remove(Object value)`.

### Special example: removing a value

```java
import java.util.ArrayList;

public class RemoveExample {
    public static void main(String[] args) {
        ArrayList<Integer> nums = new ArrayList<>();

        nums.add(10);
        nums.add(20);
        nums.add(30);

        boolean removed = nums.remove(Integer.valueOf(20));

        System.out.println(removed);
        System.out.println(nums);
    }
}
```

Output:

```text
true
[10, 30]
```

## 2. How to iterate over an ArrayList

### Method A: Traditional for-loop

```java
for (int i = 0; i < nums.size(); i++) {
    System.out.println(nums.get(i));
}
```

Use this when you need the index.

### Method B: Enhanced for-loop

```java
for (int num : nums) {
    System.out.println(num);
}
```

Use this when you only need the values.

### Method C: forEach with a lambda

```java
nums.forEach(num -> System.out.println(num));
```

This is useful to recognize, but the traditional and enhanced for-loops are sufficient for most of your initial DSA problems.

## 3. Time complexity

For an `ArrayList`:

| Operation               | Typical time complexity |
| ----------------------- | ----------------------- |
| `get(index)`            | O(1)                    |
| `set(index, value)`     | O(1)                    |
| `add(value)` at the end | Amortized O(1)          |
| `add(index, value)`     | O(n)                    |
| `remove(index)`         | O(n) in general         |
| `contains(value)`       | O(n)                    |
| `indexOf(value)`        | O(n)                    |

Appending is amortized O(1), meaning occasional resizing may take longer, but the average cost per append remains constant over a sequence of operations.

### Interview insight

Suppose you have an `ArrayList` containing one million integers.

Calling:

```java
nums.get(500000);
```

is typically O(1).

But calling:

```java
nums.contains(500000);
```

is O(n) in the worst case because Java may need to scan the list.

This distinction matters when selecting a data structure.

## 4. Solved example: reverse an ArrayList

**Problem:** Reverse the order of the elements without creating another list.

```java
import java.util.ArrayList;

public class ReverseList {
    public static void reverse(ArrayList<Integer> nums) {
        int left = 0;
        int right = nums.size() - 1;

        while (left < right) {
            int temp = nums.get(left);

            nums.set(left, nums.get(right));
            nums.set(right, temp);

            left++;
            right--;
        }
    }

    public static void main(String[] args) {
        ArrayList<Integer> nums = new ArrayList<>();

        nums.add(10);
        nums.add(20);
        nums.add(30);
        nums.add(40);

        reverse(nums);

        System.out.println(nums);
    }
}
```

Output:

```text
[40, 30, 20, 10]
```

Time complexity: O(n).

Auxiliary space complexity: O(1), excluding the existing list.

### When should you use ArrayList in DSA?

Use it when you need:

* A dynamically sized sequence.
* A list of results.
* A collection of nodes or values.
* A return type such as `List<Integer>`.
* Efficient indexed access.

Don't automatically replace every array with an `ArrayList`. Arrays remain useful when the problem supplies an array or when fixed-size storage is preferable.

# PART 4 — HashMap

## Lesson 3: The most important collection for Day 2

A `HashMap` stores key-value pairs.

For example:

```text
101 -> "Alice"
102 -> "Bob"
103 -> "Charlie"
```

You can retrieve a value using its key without scanning every entry in the map in the average case.

This makes `HashMap` extremely useful for frequency counting, lookups, and problems involving complements.

## 1. Creating a HashMap

```java
import java.util.HashMap;

HashMap<Integer, Integer> map = new HashMap<>();
```

Here:

* The first `Integer` represents the key.
* The second `Integer` represents the value.

For a frequency map, both happen to be integers.

Example:

```java
HashMap<String, Integer> scores = new HashMap<>();

scores.put("Alice", 90);
scores.put("Bob", 85);

System.out.println(scores.get("Alice"));
```

Output:

```text
90
```

## 2. Essential HashMap methods

| Method                            | Purpose                            |
| --------------------------------- | ---------------------------------- |
| `put(key, value)`                 | Insert or update a mapping         |
| `get(key)`                        | Retrieve a value or return null    |
| `getOrDefault(key, defaultValue)` | Retrieve a value or use a fallback |
| `containsKey(key)`                | Check whether a key exists         |
| `containsValue(value)`            | Check whether a value exists       |
| `remove(key)`                     | Remove a mapping                   |
| `size()`                          | Number of mappings                 |
| `isEmpty()`                       | Check whether the map is empty     |
| `clear()`                         | Remove all mappings                |
| `keySet()`                        | Obtain a set of keys               |
| `values()`                        | Obtain a collection of values      |
| `entrySet()`                      | Obtain key-value entries           |

### Example

```java
import java.util.HashMap;

public class MapDemo {
    public static void main(String[] args) {
        HashMap<String, Integer> map = new HashMap<>();

        map.put("Alice", 90);
        map.put("Bob", 80);

        map.put("Alice", 95);

        System.out.println(map.get("Alice"));
        System.out.println(map.containsKey("Bob"));
        System.out.println(map.size());

        map.remove("Bob");

        System.out.println(map);
    }
}
```

Output:

```text
95
true
1
{Alice=95}
```

Notice that inserting `"Alice"` again updates the existing mapping instead of creating a duplicate key.

## 3. The most important method: getOrDefault()

Suppose:

```java
int[] nums = {1, 2, 2, 3, 3, 3};
```

You want to count how often each number occurs.

You could write:

```java
HashMap<Integer, Integer> freq = new HashMap<>();

for (int num : nums) {
    if (freq.containsKey(num)) {
        freq.put(num, freq.get(num) + 1);
    } else {
        freq.put(num, 1);
    }
}
```

But Java offers a cleaner approach:

```java
HashMap<Integer, Integer> freq = new HashMap<>();

for (int num : nums) {
    freq.put(num, freq.getOrDefault(num, 0) + 1);
}
```

The final frequency map contains:

```text
1 -> 1
2 -> 2
3 -> 3
```

Why does this work?

For the first occurrence of `2`:

```java
freq.getOrDefault(2, 0)
```

returns `0`.

You then store:

```java
freq.put(2, 1);
```

For the second occurrence:

```java
freq.getOrDefault(2, 0)
```

returns `1`.

You then store:

```java
freq.put(2, 2);
```

This is one of the most valuable lines of Java code to memorize for DSA.

### Iterate over keys


### Iterate over values

```java
for (Integer value : map.values()) {

```

### Iterate over key-value pairs

## 5. Solved example: count character frequencies

**Problem:** Count how often each character occurs in a string.

```java
import java.util.HashMap;
import java.util.Map;

public class CharacterFrequency {
    public static void main(String[] args) {
        String text = "banana";

        HashMap<Character, Integer> freq = new HashMap<>();

        for (char ch : text.toCharArray()) {
            freq.put(ch, freq.getOrDefault(ch, 0) + 1);
        }

        for (Map.Entry<Character, Integer> entry : freq.entrySet()) {
            System.out.println(
                entry.getKey() + ": " + entry.getValue()
            );
        }
    }
}
```

The frequencies are:

```text
b: 1
a: 3
n: 2
```

The output order is not guaranteed.

### What is `toCharArray()`?

It converts a string into a character array.

```java

```

Now you can iterate over the characters:

```java

    System.out.println(ch);
}
```

This is especially useful for string DSA problems.

## 6. Solved example: Two Sum

This is one of the most important problems you can solve after today's study.

**Problem:** Given an integer array and a target, return the indices of two numbers that add up to the target.

Assume exactly one valid answer exists.

Example:

```text
nums = [2, 7, 11, 15]
target = 9
```

Output:

```text
[0, 1]
```

### Approach

For every number:

1. Calculate the complement: `target - num`.
2. Check whether the complement has already appeared.
3. If it has, return the two indices.
4. Otherwise, record the current number and its index.

### Complete Java solution

```java
import java.util.HashMap;
import java.util.Arrays;

public class TwoSum {
    public static int[] twoSum(int[] nums, int target) {
        HashMap<Integer, Integer> seen = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];

            if (seen.containsKey(complement)) {
                return new int[] {
                    seen.get(complement), i
                };
            }

            seen.put(nums[i], i);
        }

        return new int[0];
    }

    public static void main(String[] args) {
        int[] nums = {2, 7, 11, 15};
        int target = 9;

        System.out.println(
            Arrays.toString(twoSum(nums, target))
        );
    }
}
```

Output:

```text
[0, 1]
```

The `Arrays` import is used only to print the resulting array conveniently.

### Why do we check before inserting?

Suppose the array is:

```text
[3, 3]
```

And the target is:

```text
6
```

At index `0`, the map is empty. We store:

```text
3 -> 0
```

At index `1`, we look for the complement `3`. It exists, so we return:

```text
[0, 1]
```

This prevents an element from being paired with itself.

**Time complexity:** O(n) expected.

**Space complexity:** O(n).

```java
import java.util.HashSet;
```

## 2. Solved example: detect duplicates

**Problem:** Determine whether an integer array contains any duplicate values.

```java
import java.util.HashSet;

public class ContainsDuplicate {
    public static boolean containsDuplicate(int[] nums) {
        HashSet<Integer> seen = new HashSet<>();

        for (int num : nums) {
            if (!seen.add(num)) {
                return true;
            }
        }

        return false;
    }

    public static void main(String[] args) {
        int[] nums = {1, 2, 3, 1};

        System.out.println(containsDuplicate(nums));
    }
}
```

Output:

```text
true
```

Notice the shortcut:

```java
if (!seen.add(num))
```

You do not need to check `contains()` first. `add()` already tells you whether the value was new.

This is a useful Java pattern.

## 3. HashMap versus HashSet

| Situation                                | Choose          |
| ---------------------------------------- | --------------- |
| Determine whether a value exists         | `HashSet`       |
| Count how many times a value appears     | `HashMap`       |
| Store a value associated with a key      | `HashMap`       |
| Find whether a pair or complement exists | Often `HashMap` |
| Find unique elements                     | `HashSet`       |
| Group elements by a property             | Often `HashMap` |

Both generally offer O(1) expected-time membership or lookup operations, although their worst-case behavior can be worse.

# PART 6 — Stack, Queue, and Deque

## Lesson 5: Stack

A stack follows **LIFO: Last In, First Out**.

Imagine a stack of plates.

The last plate you place on top is the first one you remove.

Java has a legacy `Stack` class, but for most modern DSA implementations, using `Deque` with `ArrayDeque` is a good choice.

```java
import java.util.ArrayDeque;
import java.util.Deque;

Deque<Integer> stack = new ArrayDeque<>();
```

### Essential methods

| Method        | Purpose                          |
| ------------- | -------------------------------- |
| `push(value)` | Push onto the top                |
| `peek()`      | Examine the top                  |
| `pop()`       | Remove and return the top        |
| `isEmpty()`   | Check whether the stack is empty |
| `size()`      | Number of elements               |

Example:

```java
Deque<Integer> stack = new ArrayDeque<>();

stack.push(10);
stack.push(20);
stack.push(30);

System.out.println(stack.peek());
System.out.println(stack.pop());
System.out.println(stack.pop());
System.out.println(stack.isEmpty());
```

Output:

```text
30
30
20
false
```

### Important: empty stack behavior

With `ArrayDeque`:

* `peek()` returns `null` when empty.
* `pop()` throws `NoSuchElementException` when empty.

Therefore, check:

```java
if (!stack.isEmpty()) {
    int top = stack.pop();
}
```

Also, `ArrayDeque` does not allow `null` elements.

## 1. Solved example: Valid Parentheses

This is one of the most important stack problems in NeetCode 150.

**Problem:** Determine whether a string containing brackets is valid.

Examples:

```text
"()"     -> true
"()[]{}" -> true
"(]"     -> false
"([)]"   -> false
"{[]}"   -> true
```

### Complete Java solution

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class ValidParentheses {
    public static boolean isValid(String s) {
        Deque<Character> stack = new ArrayDeque<>();

        for (char ch : s.toCharArray()) {
            if (ch == '(' || ch == '[' || ch == '{') {
                stack.push(ch);
            } else {
                if (stack.isEmpty()) {
                    return false;
                }

                char top = stack.pop();

                if (ch == ')' && top != '(') {
                    return false;
                }

                if (ch == ']' && top != '[') {
                    return false;
                }

                if (ch == '}' && top != '{') {
                    return false;
                }
            }
        }

        return stack.isEmpty();
    }

    public static void main(String[] args) {
        System.out.println(isValid("()[]{}"));
        System.out.println(isValid("([)]"));
        System.out.println(isValid("{[]}"));
    }
}
```

Output:

```text
true
false
true
```

### Why check `stack.isEmpty()` before popping?

Consider:

```text
")"
```

The first character is a closing bracket.

No opening bracket exists to match it.

If you immediately call `pop()`, the program throws an exception.

Instead, the algorithm returns `false`.

### Why check the stack at the end?

Consider:

```text
"((("
```

Every character gets pushed onto the stack.

No invalid closing bracket appears.

But the brackets are not balanced.

The remaining stack elements reveal that unmatched opening brackets remain.

Therefore:

```java
return stack.isEmpty();
```

is essential.

**Time complexity:** O(n).

**Space complexity:** O(n).

## Lesson 6: Queue

A queue follows **FIFO: First In, First Out**.

Imagine people waiting in a line.

The first person to enter the line is the first person served.

In Java:

```java
import java.util.ArrayDeque;
import java.util.Queue;

Queue<Integer> queue = new ArrayDeque<>();
```

### Essential methods

| Method         | Purpose                          |
| -------------- | -------------------------------- |
| `offer(value)` | Add to the back                  |
| `peek()`       | Examine the front                |
| `poll()`       | Remove and return the front      |
| `isEmpty()`    | Check whether the queue is empty |
| `size()`       | Number of elements               |

Example:

```java
Queue<Integer> queue = new ArrayDeque<>();

queue.offer(10);
queue.offer(20);
queue.offer(30);

System.out.println(queue.peek());
System.out.println(queue.poll());
System.out.println(queue.poll());
```

Output:

```text
10
10
20
```

### Why prefer offer() and poll()?

The methods `offer()` and `poll()` are convenient when an empty collection is a normal possibility.

For a queue:

* `poll()` returns `null` when empty.
* `remove()` throws `NoSuchElementException` when empty.
* `peek()` returns `null` when empty.
* `element()` throws `NoSuchElementException` when empty.

Since `ArrayDeque` rejects null elements, a `null` result from its `poll()` or `peek()` indicates that the queue is empty.

## 1. Solved example: process tasks

```java
import java.util.ArrayDeque;
import java.util.Queue;

public class QueueDemo {
    public static void main(String[] args) {
        Queue<String> tasks = new ArrayDeque<>();

        tasks.offer("Compile");
        tasks.offer("Test");
        tasks.offer("Deploy");

        while (!tasks.isEmpty()) {
            System.out.println(tasks.poll());
        }
    }
}
```

Output:

```text
Compile
Test
Deploy
```

Queues are essential for breadth-first search, or BFS, which you will study later when learning trees and graphs.

## Lesson 7: Deque

A deque is a **double-ended queue**.

You can add and remove elements at both ends.

```java
Deque<Integer> deque = new ArrayDeque<>();
```

Essential methods:

| Method              | Purpose                                  |
| ------------------- | ---------------------------------------- |
| `addFirst(value)`   | Add at the front                         |
| `addLast(value)`    | Add at the back                          |
| `removeFirst()`     | Remove the first element                 |
| `removeLast()`      | Remove the last element                  |
| `peekFirst()`       | Examine the first element                |
| `peekLast()`        | Examine the last element                 |
| `offerFirst(value)` | Attempt to add at the front              |
| `offerLast(value)`  | Attempt to add at the back               |
| `pollFirst()`       | Remove the first element, or return null |
| `pollLast()`        | Remove the last element, or return null  |

Example:

```java
Deque<Integer> deque = new ArrayDeque<>();

deque.addFirst(10);
deque.addLast(20);
deque.addFirst(5);

System.out.println(deque);
System.out.println(deque.peekFirst());
System.out.println(deque.peekLast());
```

The deque contains:

```text
[5, 10, 20]
```

The first element is `5`, and the last element is `20`.

### Why does this matter?

A deque can implement:

* A stack.
* A queue.
* A monotonic deque for sliding-window problems.
* Algorithms that process elements from both ends.

For now, master its stack usage. You will revisit its advanced applications later.

# PART 7 — PriorityQueue and heaps

## Lesson 8: PriorityQueue

A `PriorityQueue` removes elements according to priority rather than insertion order.

In Java, the default `PriorityQueue<Integer>` is a min-heap.

That means its head is the smallest element.

```java
import java.util.PriorityQueue;

PriorityQueue<Integer> heap = new PriorityQueue<>();

heap.offer(30);
heap.offer(10);
heap.offer(20);

System.out.println(heap.peek());
System.out.println(heap.poll());
System.out.println(heap.poll());
```

Output:

```text
10
10
20
```

The smallest element is removed first.

## 1. Essential methods

| Method         | Purpose                              |
| -------------- | ------------------------------------ |
| `offer(value)` | Insert an element                    |
| `add(value)`   | Insert an element                    |
| `peek()`       | Examine the highest-priority element |
| `poll()`       | Remove the highest-priority element  |
| `size()`       | Number of elements                   |
| `isEmpty()`    | Check whether empty                  |
| `clear()`      | Remove all elements                  |

The `PriorityQueue` is not fully sorted internally.

Only the head is guaranteed to be the minimum for a natural-order min-heap.

For example, printing the queue does not guarantee sorted output.

If you need all elements in priority order, repeatedly remove the head.

## 2. Creating a max-heap

A max-heap removes the largest element first.

Use:

```java
PriorityQueue<Integer> maxHeap =
    new PriorityQueue<>((a, b) -> Integer.compare(b, a));
```

The comparator reverses the natural integer ordering.

Example:

```java
import java.util.PriorityQueue;

public class MaxHeapDemo {
    public static void main(String[] args) {
        PriorityQueue<Integer> maxHeap =
            new PriorityQueue<>(
                (a, b) -> Integer.compare(b, a)
            );

        maxHeap.offer(10);
        maxHeap.offer(30);
        maxHeap.offer(20);

        System.out.println(maxHeap.poll());
        System.out.println(maxHeap.poll());
        System.out.println(maxHeap.poll());
    }
}
```

Output:

```text
30
20
10
```

### Why use Integer.compare() instead of subtraction?

Avoid writing:

```java
(a, b) -> b - a
```

for a general integer comparator.

Integer subtraction can overflow, which may produce an incorrect ordering.

Prefer:

```java
(a, b) -> Integer.compare(b, a)
```

## 3. Time complexity

| Operation | Typical complexity |
| --------- | ------------------ |
| `peek()`  | O(1)               |
| `offer()` | O(log n)           |
| `poll()`  | O(log n)           |
| `size()`  | O(1)               |

### When do you use a heap?

Common applications include:

* Finding the kth-largest element.
* Finding the kth-smallest element.
* Finding the top k frequent elements.
* Merging sorted lists.
* Graph algorithms such as Dijkstra's algorithm.

For now, you need to understand insertion, removal, and min-heap versus max-heap behavior.

# PART 8 — Linked lists in Java

## Lesson 9: Nodes, references, and null

You already understand linked-list concepts, so today's goal is to learn how to express those concepts in Java.

A typical singly linked-list node looks like this:

```java
class ListNode {
    int val;
    ListNode next;

    ListNode() {}

    ListNode(int val) {
        this.val = val;
    }

    ListNode(int val, ListNode next) {
        this.val = val;
        this.next = next;
    }
}
```

You can use this class for many linked-list problems on LeetCode.

## 1. Creating a linked list

```java
ListNode first = new ListNode(10);
ListNode second = new ListNode(20);
ListNode third = new ListNode(30);

first.next = second;
second.next = third;
```

The linked list looks like:

```text
10 -> 20 -> 30 -> null
```

The final node's `next` reference is `null`.

## 2. What does a reference mean?

Consider:

```java
ListNode current = first;
```

This does not create a new node.

Instead, `current` refers to the same node as `first`.

Therefore:

```java
current.val = 99;
```

also changes the value observed through `first`.

But:

```java
current = current.next;
```

only changes which node `current` refers to.

It does not modify `first` or alter the links in the list.

This distinction is fundamental to linked-list manipulation.

## 3. Traversing a linked list

```java
ListNode current = head;

while (current != null) {
    System.out.println(current.val);
    current = current.next;
}
```

Why use:

```java
current != null
```

instead of:

```java
current.next != null
```

Because the first condition allows you to process the final node.

The second condition stops before processing it.

It can also cause a `NullPointerException` if `current` is null.

## 4. The dummy-node technique

A dummy node is a temporary node placed before the actual head.

Example:

```java
ListNode dummy = new ListNode(0);
dummy.next = head;
```

Now the structure is:

```text
dummy -> head -> ...
```

Why is this useful?

Many linked-list operations treat the head differently from other nodes.

A dummy node simplifies operations that may remove or replace the original head.

For example, removing every occurrence of a value:

```java
public static ListNode removeElements(ListNode head, int val) {
    ListNode dummy = new ListNode(0, head);

    ListNode current = dummy;

    while (current.next != null) {
        if (current.next.val == val) {
            current.next = current.next.next;
        } else {
            current = current.next;
        }
    }

    return dummy.next;
}
```

Suppose:

```text
head = 1 -> 2 -> 6 -> 3 -> 6
val = 6
```

The returned list is:

```text
1 -> 2 -> 3
```

### Why do we inspect `current.next`?

Because we need to change the link that points to the node we want to remove.

When the next node matches the target:

```java
current.next = current.next.next;
```

skips that node.

We do not advance `current` in that branch because the new next node may also need to be removed.

## 5. Null safety

A `NullPointerException` occurs when you try to access a field or method through a null reference.

This is unsafe:

```java
ListNode current = null;

System.out.println(current.val);
```

This is safe:

```java
if (current != null) {
    System.out.println(current.val);
}
```

**Interview habit:** Before dereferencing a node, know why it cannot be null or check that it is not null.

# PART 9 — Java equality and hashing

## Lesson 10: `==`, `equals()`, and `hashCode()`

These concepts matter when working with maps, sets, and objects.

### 1. Primitive equality

```java
int a = 10;
int b = 10;

System.out.println(a == b);
```

Output:

```text
true
```

For primitives, `==` compares values.

### 2. String equality

```java
String a = new String("hello");
String b = new String("hello");

System.out.println(a == b);
System.out.println(a.equals(b));
```

Output:

```text
false
true
```

For objects, `==` compares references: whether both references point to the same object.

`String.equals()` compares the string contents.

For example:

```java
if (a.equals(b)) {
    System.out.println("Same content");
}
```

For strings, use `.equals()` when you want to compare contents.

### 3. Why does this matter for HashMap?

A `HashMap` uses an object's hash code to help locate a bucket and uses equality checks to distinguish matching keys.

For classes that override `equals()`, the corresponding `hashCode()` implementation must satisfy this contract:

**If two objects are equal according to `equals()`, they must return the same hash code.**

If you create a custom class to use as a key in a `HashMap` or as an element in a `HashSet`, implement both methods consistently.

For example, a class representing a coordinate might define equality based on its `x` and `y` fields.

If you don't implement suitable equality and hashing, two separate objects with identical coordinate values may still be treated as different keys.

You do not need to implement custom hashing for most introductory LeetCode problems today, but you should understand the concept.

## Lesson 11: The `Arrays` and `Collections` classes

Java provides utility methods that save you from writing common operations repeatedly.

Remember the distinction:

* `Arrays` provides utilities for arrays.
* `Collections` provides utilities for collections.

### 1. Sorting an array

```java
import java.util.Arrays;

int[] nums = {5, 2, 8, 1};

Arrays.sort(nums);

System.out.println(Arrays.toString(nums));
```

Output:

```text
[1, 2, 5, 8]
```

For an ordinary primitive `int[]`, this is the standard sorting method.

### 2. Sorting an ArrayList

```java
import java.util.ArrayList;
import java.util.Collections;

ArrayList<Integer> nums = new ArrayList<>();

nums.add(5);
nums.add(2);
nums.add(8);
nums.add(1);

Collections.sort(nums);

System.out.println(nums);
```

Output:

```text
[1, 2, 5, 8]
```

You can also write:

```java
nums.sort(null);
```

for natural ordering.

### 3. Reversing a list

```java
Collections.reverse(nums);
```

This modifies the list in place.

It does not return a new reversed list.

### 4. Finding the minimum and maximum

```java
int min = Collections.min(nums);
int max = Collections.max(nums);
```

These methods work on collections of comparable elements.

For an array:

```java
int[] nums = {5, 2, 8, 1};
```

there is no direct `Arrays.min(nums)` method. You can calculate the minimum and maximum with a loop or use streams where appropriate.

For Day 2, a simple loop is more valuable to understand.

### 5. Binary search

For a sorted array:

```java
int[] nums = {1, 3, 5, 7, 9};

int index = Arrays.binarySearch(nums, 5);
```

The result is:

```text
2
```

Important: binary search requires the array to be sorted according to the relevant ordering.

If the target is absent, the returned value is negative and encodes the insertion point. Don't interpret every negative result as an ordinary index.

### 6. Copying an array

```java
int[] copy = Arrays.copyOf(nums, nums.length);
```

This creates a new array with the same length and copies the elements.

For a one-dimensional primitive array, the values are copied.

For arrays of object references, the references are copied, not the underlying objects.

### 7. Useful comparison methods

```java
Arrays.equals(a, b);
Arrays.toString(nums);
Arrays.copyOf(nums, nums.length);
```

* `Arrays.equals()` compares array contents.
* `Arrays.toString()` provides a readable representation.
* `Arrays.copyOf()` creates a copy.

These are extremely useful for testing DSA solutions.

## Lesson 12: The exceptions you need to recognize

You already encountered exceptions on Day 1. Today, focus on exceptions that occur while manipulating collections and nodes.

| --------------------------------- | ----------------------------------------------------------- |
| `NullPointerException`            | Dereferencing null or unboxing a null wrapper               |

### Example: invalid index

```java
ArrayList<Integer> nums = new ArrayList<>();

System.out.println(nums.get(5));
```

This throws an `IndexOutOfBoundsException`.

### Example: safe index access

```java
if (index >= 0 && index < nums.size()) {
    System.out.println(nums.get(index));
}
```

### Example: empty stack

```java
Deque<Integer> stack = new ArrayDeque<>();

if (!stack.isEmpty()) {
    System.out.println(stack.pop());

```

### Example: removing while iterating

This pattern can cause problems:

```java

    if (num == 10) {

}
```

Modifying a collection structurally while using its enhanced for-loop can trigger a `ConcurrentModificationException`.

For this integer example, the predicate works through unboxing. In general, be aware of null values when writing predicates.

# PART 12 — Comparators and lambdas

## Lesson 13: How Java decides ordering

A comparator defines how two objects should be ordered.

The comparison result follows this rule:

* Negative: the first value should come before the second.
* Zero: the values are equal under the comparator.
* Positive: the first value should come after the second.

Example:

```java
PriorityQueue<Integer> maxHeap =
    new PriorityQueue<>(
        (a, b) -> Integer.compare(b, a)
    );
```

The lambda expression:

```java
(a, b) -> Integer.compare(b, a)
```

defines a comparator that places larger integers first.

You will encounter lambda expressions frequently in Java DSA.

### Example: sorting strings by length

```java
import java.util.ArrayList;
import java.util.Comparator;

public class SortByLength {
    public static void main(String[] args) {
        ArrayList<String> words = new ArrayList<>();

        words.add("banana");
        words.add("kiwi");
        words.add("apple");
        words.add("fig");

        words.sort(
            Comparator.comparingInt(String::length)
        );

        System.out.println(words);
    }
}
```

Output:

```text
[fig, kiwi, apple, banana]
```

Here:

```java
String::length
```

is a method reference.

You don't need to master method references today, but you should recognize them.

### Example: custom ordering for a heap

Suppose you want to store two-element integer arrays and prioritize the smallest first element.

```java
PriorityQueue<int[]> heap = new PriorityQueue<>(
    (a, b) -> Integer.compare(a[0], b[0])
);
```

You can insert:

```java
heap.offer(new int[] {5, 100});
heap.offer(new int[] {2, 200});
heap.offer(new int[] {8, 300});
```

Then:

```java
int[] smallest = heap.poll();
System.out.println(smallest[0]);
```

Output:

```text
2
```

This technique is useful for intervals, pairs, coordinates, and graph algorithms.

# PART 15 — Additional solved examples

We have already solved Two Sum, Contains Duplicate, Valid Parentheses, character frequencies, and a linked-list removal problem.

Let's add three more examples.

## Example 1: Find the first unique character

**Problem:** Given a string, return the index of its first non-repeating character. Return `-1` if none exists.

Example:

```text
s = "leetcode"
```

Output:

```text
0
```

The character `l` occurs once and is the first character.

### Solution

```java
import java.util.HashMap;

public class FirstUniqueCharacter {
    public static int firstUniqChar(String s) {
        HashMap<Character, Integer> freq = new HashMap<>();

        for (char ch : s.toCharArray()) {
            freq.put(ch, freq.getOrDefault(ch, 0) + 1);
        }

        for (int i = 0; i < s.length(); i++) {
            if (freq.get(s.charAt(i)) == 1) {
                return i;
            }
        }

        return -1;
    }

    public static void main(String[] args) {
        System.out.println(firstUniqChar("leetcode"));
        System.out.println(firstUniqChar("aabb"));
    }
}
```

Output:

```text
0
-1
```

The algorithm uses two passes:

1. Count every character.
2. Find the first character whose count equals one.

**Time complexity:** O(n) expected.

**Space complexity:** O(k), where `k` is the number of distinct characters stored. For a fixed-size alphabet, this is O(1).

## Example 2: Find the kth-largest element

**Problem:** Return the kth-largest element in an integer array.

Example:

```text
nums = [3, 2, 1, 5, 6, 4]
k = 2
```

Output:

```text
5
```

The second-largest element is `5`.

### Solution using a min-heap

Maintain a heap containing at most `k` elements.

```java
import java.util.PriorityQueue;

public class KthLargest {
    public static int findKthLargest(int[] nums, int k) {
        PriorityQueue<Integer> heap = new PriorityQueue<>();

        for (int num : nums) {
            heap.offer(num);

            if (heap.size() > k) {
                heap.poll();
            }
        }

        return heap.peek();
    }

    public static void main(String[] args) {
        int[] nums = {3, 2, 1, 5, 6, 4};

        System.out.println(findKthLargest(nums, 2));
    }
}
```

Output:

```text
5
```

Why does this work?

We retain only the `k` largest elements seen so far.

If the heap grows beyond size `k`, we remove the smallest element.

At the end, the heap contains the `k` largest elements, and its minimum is the kth-largest value.

**Time complexity:** O(n log k).

**Auxiliary space complexity:** O(k).

## Example 3: Implement a stack using Deque

**Problem:** Build a small class that exposes stack operations using Java's `Deque`.

```java
import java.util.ArrayDeque;
import java.util.Deque;

class MyStack {
    private final Deque<Integer> stack = new ArrayDeque<>();

    public void push(int value) {
        stack.push(value);
    }

    public int pop() {
        return stack.pop();
    }

    public int top() {
        return stack.peek();
    }

    public boolean isEmpty() {
        return stack.isEmpty();
    }
}

public class StackImplementation {
    public static void main(String[] args) {
        MyStack stack = new MyStack();

        stack.push(10);
        stack.push(20);

        System.out.println(stack.top());
        System.out.println(stack.pop());
        System.out.println(stack.top());
        System.out.println(stack.isEmpty());
    }
}
```

Output:

```text
20
20
10
false
```

This example combines classes, fields, methods, access modifiers, and collection operations.

Note that this simple implementation assumes the caller does not call `top()` or `pop()` on an empty stack. A more defensive implementation could define its empty-stack behavior explicitly.
