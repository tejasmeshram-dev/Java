ART 18 — COMMON MISTAKES YOU MUST AVOID

Before finishing Day 2, review these mistakes.

Mistake 1: Using length() on an ArrayList

Incorrect:

list.length()

Correct:

list.size()

For arrays:

nums.length

For strings:

s.length()

For collections such as ArrayList:

list.size()
Mistake 2: Using primitive types in generics

Incorrect:

ArrayList<int> list = new ArrayList<>();

Correct:

ArrayList<Integer> list = new ArrayList<>();
Mistake 3: Confusing map keys and values
map.put(10, 20);

The key is 10.

The value is 20.

Mistake 4: Forgetting to update a frequency

Incorrect:

freq.put(num, 1);

This resets the frequency to 1 every time the number appears.

Correct:

freq.put(num, freq.getOrDefault(num, 0) + 1);
Mistake 5: Popping from an empty stack

Incorrect:

char top = stack.pop();

This throws an exception if the stack is empty.

Correct:

if (stack.isEmpty()) {
    return false;
}

char top = stack.pop();
Mistake 6: Assuming a PriorityQueue is sorted

A heap guarantees access to its highest-priority element, not sorted iteration.

Use repeated poll() calls when you need priority order.

Mistake 7: Reversing a linked list without saving the next node

Incorrect:

current.next = prev;
current = current.next;

After changing current.next, the reference to the original next node is lost.

Correct:

ListNode next = current.next;

current.next = prev;

prev = current;
current = next;
Mistake 8: Forgetting to return the new head

After reversing a linked list, the original head becomes the tail.

The new head is prev.

Correct:

return prev;
Mistake 9: Using a list for repeated membership checks

If you repeatedly write:

list.contains(value);

inside a large loop, the solution may become O(n²).

If you only need membership information, consider a HashSet.

Mistake 10: Ignoring edge cases

Every solution should be tested with:

Empty input, if allowed.
One element.
Duplicate values.
No matching values.
Boundary values.
Invalid input, if the problem allows it.
