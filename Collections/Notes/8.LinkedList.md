PART 8 — LINKED LISTS IN JAVA
29. Understand nodes and references

You already understand linked lists conceptually, so this section focuses on implementing them in Java.

A singly linked list consists of nodes.

Each node contains:

A value.
A reference to the next node.

For example:

10 -> 20 -> 30 -> null

The first node is the head.

The final node points to null.

Define a ListNode
class ListNode {

    int val;
    ListNode next;

    ListNode() {}

    ListNode(int val) {
        this.val = val;
    }

    ListNode(int val, ListNode next) {
        this.val = val;
        this.next = next;
    }
}

These constructors allow you to create nodes in different ways.

ListNode a = new ListNode();

ListNode b = new ListNode(10);

ListNode c = new ListNode(20, b);

In the third statement, c.next refers to b.

Creating a list manually
ListNode head = new ListNode(10);
head.next = new ListNode(20);
head.next.next = new ListNode(30);

The resulting list is:

10 -> 20 -> 30 -> null
30. The most important concept: references

Consider:

ListNode current = head;

This does not create a new node.

It creates another reference to the same node.

Suppose:

head
 |
 v
[10] -> [20] -> [30] -> null

After:

ListNode current = head;

both variables refer to the node containing 10.

When you write:

current = current.next;

the current reference moves to the node containing 20.

It does not change head.

Another important distinction
current = current.next;

moves the reference.

But:

current.next = current.next.next;

changes a link in the list.

These operations are fundamentally different.

The first changes which node a variable refers to.

The second changes the structure of the linked list.

Confusing them can break linked-list solutions.

31. Traversing a linked list

A standard traversal looks like this:

ListNode current = head;

while (current != null) {

    System.out.println(current.val);

    current = current.next;
}
Why use current != null?

Because the last node's next reference is null.

Once current becomes null, there are no more nodes to process.

Common error
while (current.next != null) {
    // ...
}

This assumes current is not null.

If head itself is null, evaluating current.next throws a NullPointerException.

Also, this loop stops before processing the final node.

Use:

while (current != null)

when you need to process every node.

32. Dummy nodes

A dummy node is an extra node placed before the actual head.

It simplifies operations that might change the head.

Example:

ListNode dummy = new ListNode(0);
dummy.next = head;

The structure becomes:

dummy -> 10 -> 20 -> 30 -> null

Now dummy.next always refers to the current head of the real list.

When you're finished:

return dummy.next;
Why is this useful?

Consider removing the first node.

Without a dummy node, you may need separate logic:

if (head != null && head.val == target) {
    head = head.next;
}

Then you must handle the other nodes separately.

A dummy node lets you use a more uniform approach.

General rule

Use a dummy node when an operation might:

Delete the original head.
Insert before the original head.
Build a new list incrementally.
Simplify handling of empty lists.

You will use dummy nodes frequently in linked-list coding assessments.

33. Solved problem: Reverse a linked list

Problem: Given the head of a singly linked list, reverse the list and return the new head.

Example:

Input:
1 -> 2 -> 3 -> null

Output:
3 -> 2 -> 1 -> null
The three-reference technique

You need:

prev: The previous node.
current: The node currently being processed.
next: A temporary reference to the next node.

Why do you need next?

Because once you overwrite current.next, you would otherwise lose access to the rest of the list.

Complete solution
class Solution {

    public ListNode reverseList(ListNode head) {

        ListNode prev = null;
        ListNode current = head;

        while (current != null) {

            ListNode next = current.next;

            current.next = prev;

            prev = current;

            current = next;
        }

        return prev;
    }
}
Dry run

Initially:

prev = null

current -> 1 -> 2 -> 3 -> null

First iteration:

next = 2
1.next = null
prev = 1
current = 2

Second iteration:

next = 3
2.next = 1
prev = 2
current = 3

Third iteration:

next = null
3.next = 2
prev = 3
current = null

Now:

3 -> 2 -> 1 -> null

Return prev.

Complexity
Time: O(n).
Auxiliary space: O(1).
Edge cases
Input	Expected output
null	null
1 -> null	1 -> null
1 -> 2 -> null	2 -> 1 -> null
1 -> 2 -> 3 -> null	3 -> 2 -> 1 -> null

The algorithm handles all of them.

34. Solved problem: Remove elements from a linked list

Problem: Given the head of a linked list and a target value, remove every node whose value equals the target.

Example:

Input:
1 -> 2 -> 6 -> 3 -> 6 -> null

Target:
6

Output:
1 -> 2 -> 3 -> null
Complete solution using a dummy node
class Solution {

    public ListNode removeElements(ListNode head, int val) {

        ListNode dummy = new ListNode(0);
        dummy.next = head;

        ListNode current = dummy;

        while (current.next != null) {

            if (current.next.val == val) {

                current.next = current.next.next;

            } else {

                current = current.next;
            }
        }

        return dummy.next;
    }
}
Why do we inspect current.next?

Because the current node is the node before the one we may want to remove.

If:

current -> [6] -> [3]

then:

current.next = current.next.next;

changes the link to:

current -> [3]

The node containing 6 is no longer linked into the list.

Important edge cases
The list is empty.
The first node must be removed.
Every node must be removed.
No nodes match the target.
Multiple consecutive nodes match the target.

The dummy-node technique handles these cases cleanly.
